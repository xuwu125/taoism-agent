## 二、完整口播转写（时间轴，ASR + 人工最小校订）

> 说明：以下为机器转写后的校订版。明显同音错字已订正并标注，无法确认的句子标 `[听录存疑]`，未改动原意。

**【0:00–0:17｜钩子：符 = prompt，急急如律令 = 回车】**
道士画的符，其实是一段 prompt。2000 年前的 AI 工程。「急急如律令」你一定听过，但它根本不是咒语，而是秦汉公文的标准结尾「如律令」，意思是「按照法令立即执行」，说白了就是敲下回车键。宋人早有解释，犹经云「符道奉行」`[听录存疑]`。

**【0:17–1:00｜符 = 凭证 = 古代 API Key；天师道把公文格式搬进人神通信】**
再看「符」字本身，《说文解字》：「符，信也」，分而相合——一块竹符劈成两半，合得上才算验证通过。所以符就是凭证，就是古代的 API Key。受箓时师徒还要剖开金环各执一半，像不像一对密钥？东汉末年，张道陵创立天师道，他把朝廷公文的格式搬进了人神之间的通信，从此一张符就是一份格式严格的指令。我们把它拆开看……

**【1:00–1:43｜拆符十步，收束为「一张符 = 一个完整 AI Agent」】**
符头是服务地址，指令发往哪个天庭；神明名号就是 Model ID，请哪位神就是调哪个模型。敕令是 API Key，没有授权神不理你。捆仙绳是运行框架，把神力约束在规矩里。天柱是 System Prompt，天定的规矩，优先级最高；地柱是 User Prompt，凡人的诉求；所请事项就是任务目标（Goal），越明确越灵验。风火轮是工具调用，调兵遣将；符胆是可复用的核心技能；符脚收笔如剑，执行—反馈—再执行。看，一张符就是一个完整的 AI Agent：目标、权限、规则、工具、技能、循环，一个不少。

**【1:43–1:54｜授箓 = 注册与授权；召将 = 多智能体协作】**
但光会画符没用，道士必须先受箓。箓就是可调遣的神将名册加上权限等级，没授箓就画符，天庭直接拒绝访问。授箓等于注册账号、获取权限、配置工具。做法时召请雷部、火部、风部（画面另有水部）神将各司其职，这就是今天最火的多智能体协作。

**【1:43–2:00｜复文 ≈ token；焚符 ≈ 发送；画符口诀 ≈ 提示词工程】**
道经里还有一种「复文」，把几个字叠写成一个符号，像极了大模型把文字压缩成 token。写好的符要焚化，上达天庭，火光亮起，就是按下了发送键。道门口诀说：「画符不知窍，反惹鬼神笑；画符若知窍，惊得鬼神叫。」这不就是提示词工程？

**【2:00–2:40｜炼丹隐喻与二进制类比】**
更巧的是，AI 工程师自己就把训练模型叫做炼丹，GPU 是丹炉，调参是火候，训练崩了叫炸炉。再往深处看，阴爻阳爻就是 0 和 1；1703 年莱布尼茨在伏羲卦图里看到了他的二进制；「道生一，一生二，二生三，三生万物」，这不就是生成式 AI？

**【2:40–2:51｜科学拆解：符为什么「灵」】**
那符真的灵吗？我们用科学拆一拆。第一，心理学：哈佛 2016 年的实验发现，只要相信这是仪式，焦虑就会下降、表现更好。第二，神经科学：符水治病靠的是期待，大脑一相信就会调动多巴胺和内啡肽（安慰剂效应）。第三，化学：朱砂是硫化汞，含汞八成以上，符水千万别喝。

**【2:51–3:05｜反转收束与 CTA】**
所以真相是：2000 年来，被 Prompt 的一直是人脑。人们对着天空写了 2000 年 prompt，却从没收到过回复——直到今天这一次，神回话了。从驱动人脑，到驱动 AI，道家的符就是人类最早的 Prompt。关注我，用 AI 重读中国文化。

**主要校订记录**（ASR → 校订）：我么说→我们说；孚/孚字→符；受禄→受箓；各吃一半→各执一半；密药→密钥；地柱是 userprompt 与天柱 System Prompt 的连读误切已按画面还原；符角→符脚；aiageagent→AI Agent；赋文→复文；「阴爻阳爻就是0和11703年」→「0 和 1；1703 年」；那么福真的灵吗→那符真的灵吗；服 prompt→被 Prompt；到家的符→道家的符。

## 三、核心论证链：一张符 = 一个完整的 AI Agent

视频用「10 步拆符」递进，每步给一张符纸局部特写 + 编号 `NN / 10` + 英文技术名 + 中文小字 + 一行伪代码，最后用一张总图收束。按画面逐项核对如下：

| # | 符的部位 | 画面英文 | 视频给出的技术含义 | 对应现代 Agent 组件 |
|---|---|---|---|---|
| 01 | 符头 | API Base URL | 服务地址：指令发往哪个天庭 | 供应商 / 端点路由 |
| 02 | 神明名号 | Model ID | 请哪位神 = 调哪个模型 | 模型选择 |
| 03 | 敕令 | API Key | 「没有授权，神不理你」；伪代码 `api_key = "sk-敕令-****"` | 鉴权凭证 |
| 04 | 捆仙绳 | Agent Harness | 把神力约束在规矩里 | 运行框架 / 约束层 |
| 05 | 天柱 | System Prompt | 「天定的规矩，优先级最高」；伪代码 `system: "奉天行事，不得违令"` | 系统指令 |
| 06 | 地柱 | User Prompt | 凡人的诉求 | 用户输入 |
| 07 | 所请事项 | Goal | 任务目标，越明确越灵验 | 目标 / 成功判据 |
| 08 | 风火轮 | Tool Call | 「调兵遣将 = 调用外部能力」；伪代码 `call(tools=["雷部","火部","风部"])` | 工具调用 |
| 09 | 符胆 | Skill | 可复用的核心技能 | 技能包 / 复用单元 |
| 10 | 剑诀 · 符脚 | Output / Loop | 收笔如剑，执行—反馈—再执行 | 输出契约 + 循环 |

总图标题：**「一张符 = 一个完整的 AI Agent」**，底部一行：**「目标 · 权限 · 规则 · 工具 · 技能 · 循环，一个不少」**。

**授权层（箓）**：画面「道士必须先『受箓』」，卷轴题《太上正一盟威法箓》，列「雷部神将、六丁六甲、功曹使者、土地正神、天兵天将、五方雷将、值日功曹、城隍主者」，下方对应 `tool_1 … tool_8`；等式 **「箓 = 神将名册 + 权限等级 = Tool Registry + Permissions」**，小字引《隋书·经籍志》「箓皆素书，记诸天曹官属佐吏之名」。授箓三步：**入道（注册账号）→ 受箓（获取权限）→ 配置工具**。

**编排层（召将）**：太极图居中标注 **Orchestrator**，四周「雷部 · agent／火部 · agent／风部 · agent／水部 · agent」四节点连线，标题「召请神将，各司其职」，即多智能体协作。

**编码层（复文）**：「道经里的『复文』：几个字，叠成一个符号」，画面以「天」「雨」叠写示意 ≈ 大模型把文字压缩成 token。

**提交层（焚符）**：符纸底部燃起火光，字幕「焚符上表：烧掉，才算寄出」；另一帧是终端样式 `POST /.../messages` 与 `Enter ↵`，标题「焚化 = 按下发送」。

## 四、符箓体系的文化底本（与视频类比对照）

> 本节为文化背景补充，用于判断视频的映射是否「成体系」，不作宗教效力主张，也不把视频的类比当成学术考据。

- **符与箓是两物**：符是承载旨意、可执行的凭证文书；箓是记载神祇名讳、职司、眷属的簿籍，受箓意味着在体系中登记备案并获得法职与召遣资格，即「以箓授权，以符行事」。这与视频「箓 = Tool Registry + Permissions」的映射方向一致。
- **符体结构**：通行说法为符头（三勾象征三清或冠神尊名号）、符腹／主事神佛（作用说明）、符胆（镇守符灵，常见「罡」「井」等）、符脚（收束、终结，或踏罡步斗之意）。视频在此基础上增加了「天柱／地柱」「捆仙绳」「风火轮」等部件，属于**为类比而做的再编排**，不是严格科仪定式。
- **篆 / 云篆 / 复文**：早期符书借篆体、虫书鸟迹自成符字，笔画曲折盘纡称「天篆云书」「云篆」；《太平经》「复文」以多字叠合为一符字。视频只取「复文 ≈ token 压缩」这一层，未展开云篆。
- **书符仪轨**：净身、净口、静心、斋戒、择时、焚香设坛，书符时一笔呵成并配合咒、诀、步罡踏斗、存想，讲究「符、咒、诀、步、炁」合一；施用方式有佩带、贴置、服食、焚化。
- **制度化节点**：东汉张道陵创天师道、以正一盟威箓为核心，把汉代公文格式引入人神通信；宋元形成「三山符箓」（茅山上清、阁皂灵宝、龙虎山天师道）。视频的「2000 年前的 AI 工程」是修辞，制度史脉络大致对应汉代。

**结论**：视频抓住了符箓体系里最像软件工程的三条骨架——**结构化指令（符）、授权名册（箓）、符号编码（篆/复文）**，再补上仪轨流程（书符→敕符→焚符→回执）。这正好可以成为一套原创 Agent 运行机制的文化框架，而不是只做一层皮肤。

## 六、对本项目可复用的架构原则（10 条）

1. 提示词不是一段字符串，而是**有字段、有结构、可校验的「符」**：路由、模型、授权引用、约束、系统指令、用户诉求、目标、工具声明、技能引用、输出与循环。
2. **一张符 = 一个最小可运行 Agent 定义**，可独立保存、签名、复用、回放。
3. **符与箓分离**：符只描述「要做什么」，箓持有身份、凭证、工具注册表与权限等级；没受箓（未授权）的符不得执行。
4. **捆仙绳 = Harness 是一等公民**：预算、超时、沙箱、允许工具白名单、循环上限必须写在符里，而不是散落在运行时配置。
5. **符脚 = 输出契约 + 循环收敛条件**，让「执行—反馈—再执行」可终止、可观测。
6. **符胆 = 内容寻址的可复用技能包**，版本化，符只引用不内嵌。
7. **复文/云篆 = 序列化与编码层**：符文要能折叠成紧凑表示、能导出成文件、能按内容哈希（符印）验证完整性。
8. **太极 Orchestrator = 多智能体编排**：多个 agent 各司其职，由中心编排器分派与汇总。
9. **焚符 = 明确的提交点**：执行是不可撤销动作，之前必须有 dry-run / 校验 / 盖印 / 确认，之后必须有回执与归档。
10. **UI 同构**：界面直接呈现符纸、符部位、箓卷、法坛与焚化状态，用户操作的是「符」而非「表单」。

### 需要在工程上修正的三处「视频类比反模式」

| 视频说法 | 工程风险 | 本项目修正 |
|---|---|---|
| 「敕令 = API Key」，把密钥画进符纸并写进伪代码 | 密钥随提示词传播、易进日志/版本库/回放记录 | 符内只放**凭证引用 ID**，密钥由箓层加密保管、执行时注入，日志一律脱敏 |
| 「焚化 = 发送」，一次性不可撤销 | 误触即产生真实调用与费用 | 增加「敕符/盖印」（校验+签名）与「待焚」（dry-run + 明确确认）两态 |
| 「越明确越灵验」停留在修辞 | 无验收标准 | 把 Goal 落成可判定的成功条件与输出 schema，符脚负责收敛判据 |
