## 0. 这份规范为什么不能套通用模板

符箓台不是聊天应用，也不是配置后台。它的界面直接对应一套**道家仪轨隐喻下的多智能体运行时**：

| 体系概念 | 真实技术含义 | 界面落点 | 视觉语义 |
|---|---|---|---|
| **符** | 一张可校验、带 sha256 符印、可回放的最小 Agent 定义 | 左栏清单 / 中栏法坛 / 符文界面 | 用户操作的主对象，唯一亮面 |
| **箓** | 授权名册（`Permission` + 工具注册 + 配额） | 敕门卡片的权限轴 | 形状编码（档位），**不用颜色深浅** |
| **篆** | canonical JSON → sha256、中文 DSL、云篆描述层 | 符文正文编辑器 / 符纸版式 | 等宽 + 只读标记 |
| **法坛** | 执行层：成符 → 盖印 → 待焚 → 焚化 → 回执 | 中栏「法坛」视图 | 状态轨道 + 不可撤销分界线 |
| **太极** | 多 Agent DAG 编排（确定性串行，失败不伪装成功） | 底部抽屉 | 只读分层，无中止暗示 |
| **缴符** | append-only `sha256(prev‖event)` 链 + 脱敏 | 右栏时间线 | 单向链线，禁止任何可编辑暗示 |
| **敕门** | 高危召将前的人确认闸门（fail closed） | 朱砂卡片 | 双闸门之一，参数原文原样展示 |
| **符纸** | 一张符映射成 3:5 竖向九段热区 | 符文界面主视觉 | 金纸案台，缺段灰虚线 |
| **外宗 / 符胆** | 全局 MCP / 技能包，**只展示不管理** | 只读清单 | 青色只读语汇 |
| **回执** | 终态 + 正文 + 用量（估算要标） | 法坛 / 右栏卡片 | 判定唯一依据 |

因此本规范的**第一性原则不是「好看」，是「不撒谎」**：任何"不确定 / 不完整 / 非结论 / 只读"都必须有统一、可识别的视觉语法。设计债务在这里不是丑，是**误导**。

## 1. 五条设计哲学

1. **仪轨即界面。** 状态机是一等视觉对象（顶部状态轨道），不是一堆按钮的副产物。用户看轨道就知道走到哪一步、哪一步不可回头。
2. **暗坛金纸。** 整台是近黑深红的「玄坛」，唯一大面积亮色是符纸金。符因此自己浮出来——正好对应「用户操作对象是符，不是配置项列表」。深色不是审美偏好，是层级策略。
3. **诚实性优先。** `估算 / UNVERIFIED / 已截断 / 只读 / 纯展示 / 非回执 / 已脱敏 / 无人值守` 八种状态共用一套标注原子。不许各界面临场发挥一句小字了事。
4. **正交编码。** 权限（静态上限）与风险（逐次确认）**永不合并**成一根危险度滑块。权限用形状/档位，风险用色彩 + 确认徽标，来源单独署小字。
5. **fail-closed 是默认态。** 未授权、待确认、只读是界面的默认外观；破坏性动作必经两道闸门。绝不把「正在思考」画成假进度，也绝不把不可撤销动作做成一键即发。

### 2.3 六终态——独立色相，绝不复用

| 终态 | Token | Hex | 语义 | 为什么不能合并 |
|---|---|---|---|---|
| 归档 `Archived` | `ST_ARCHIVED` | `#6FCBA3` | 唯一正常成功出口 | — |
| 破符 `Broken` | `ST_BROKEN` | `#E0B454` | 结构/校验问题 | ≠ 授权问题 |
| 驳回 `Rejected` | `ST_REJECTED` | `#B79AD6` | 符级授权失败 | ≠ 单次「敕否」 |
| 炸炉 `Exploded` | `ST_EXPLODED` | `#F0685A` | 运行时故障 | — |
| 过坛 `TimedOut` | `ST_TIMEDOUT` | `#8FA9D4` | 超时 | 与炸炉分路 |
| 中止 `Cancelled` | `ST_CANCELLED` | `#B0A395` | **独立终态** | 既不红也不绿：不并入炸炉、不冒充成功、不回滚 |

> 这是类型级不变量的视觉映射（`core::state::can_transition` 中 `Igniting` 恰有四个互异出口 + 独立 `Cancelled`）。把失败折叠成一个红色，界面就会诱导用户去查一个不存在的 bug。`theme.rs` 有单测锁住六色互不相同。

### 2.4 权限 / 风险正交编码

| 维度 | 编码方式 | 取值 |
|---|---|---|
| `Permission`（箓层静态上限） | **三格方块的形状档位**（■□□ / ■■□ / ■■■）+ 文字 | 只读 / 受限执行 / 完全执行 |
| `RiskClass`（逐次确认强度） | **色块 + 文字** | 观察（青）/ 可变更（黄）/ 破坏性（红） |
| `Confirmation` | 无彩色小徽标 | 免确认 / 每符一次 / 每次调用 |
| `RiskSource` | 小字署名 | 外宗自述 / 覆盖表 / 未申报 / 策略下限 |

> 风险来源**未随 `ConfirmRequest` 下发**时，界面如实写「未随请求下发」，不编造一句「来自外宗自述」。

### 2.5 排版

| 阶 | px | 用途 |
|---|---|---|
| `CAPTION` | 11 | 徽标、元信息、符纸内最小字号 |
| `SMALL` | 12 | 副标、列表、说明文字（中文最小） |
| `BODY` | 14 | 正文、按钮 |
| `BODY_LG` | 16 | 卡片主标 |
| `H3` | 18 | 栏目头 |
| `H2` | 22 | 品牌字 |
| `H1` / `DISPLAY` | 28 / 36 | 预留（当前界面未用） |

字体：拉丁 egui 自带 Ubuntu；汉字内嵌思源黑体简中子集（OFL-1.1，U+4E00–9FFF），生僻字回退系统字体。**中文最小字号从历史实现的 9px 提到 11px（符纸）/ 12px（全局）**——`docs/02` 第 28 节曾自记「9.5px 下只有数字判断、没有眼睛判断」，这是修正。

### 2.6 间距 / 圆角 / 动效

- 间距 4px 基准：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`。
- 圆角：徽标 2、控件 4、卡片 6、**符纸 0**（方正传统感，与控件形成材质对比）。
- 动效：150 / 300 / 500 ms；火光 900 ms；云篆笔顺 2400 ms。**全部纯视觉，不承载任何状态判定**；鼠标场景交互目标 30px 高（≥ WCAG 2.5.8 的 24×24 AA）。

## 4. 布局与信息架构

```
┌──────────────────────────────────────────────────────────────┐
│ 坛额  朱砂方印 · 符箓台 · 系统陈述（青）  │ 太极 / 设置      │
│       └ 折叠：坛务（端点 / 工作区 / 外宗接入，仅内存生效）     │
├──────────────────────────────────────────────────────────────┤
│ 仪轨状态轨道  ○书符—○成符—○盖印—○待焚║○焚化—○归档  终态│
├───────────┬────────────────────────────────┬─────────────────┤
│ 符箓      │  中栏：[法坛 · 仪轨] [符文 · 符纸]  │ 缴符          │
│ 240px     │  法坛：当前符 → 三步动作 → 敕门 →   │ 340px         │
│ 可缩放     │        待焚计划 → 增量 → 回执      │ 可缩放         │
│           │  符文：金纸案台 + 云篆 + 表单 + 正文 │ 单向时间线     │
├───────────┴────────────────────────────────┴─────────────────┤
│ 状态栏  Tone 三态 + 终态徽标 + 字体说明 + 中文 IME 探针（折叠） │
└───────────────────────── 太极抽屉（可折叠，叠在状态栏上方）───┘
```

- 窗口默认 1280×800、最小 900×600；三栏均可缩放。
- 中栏整栏可滚（窗口矮时按钮与敕门卡片不会被裁到窗外）。
- **中栏双视图**：法坛管「仪轨与判定」，符文管「这张符长什么样、哪里还没写」。写符时不需要看仪轨按钮，执行时不需要看九段纸面。
- 断点：`< 1100px` 建议收起右栏；`< 900px` 为最小窗口，由滚动兜底。egui 桌面端不做移动端断点。

## 5. 状态机视觉映射（核心）

主链：`Draft 书符 → Formed 成符 → Sealed 盖印 → Pending 待焚 → Igniting 焚化 → Archived 归档`

- 已完成段金线、未完成段暗线；当前节点橙色实心 + 金色外环。
- **不可撤销分界线**画在 `Pending` 与 `Igniting` 之间（朱砂双竖线 + 「不可撤销」）。对应硬红线：`ignite(confirmed)` 之前必须已有 dry-run 计划且显式确认。
- 六个异常/成功终态不进轨道，另起独立徽标，避免误读成主链一环。
- 阶段推导只有一个入口 `FuluApp::current_stage()`，绘制层不自己猜状态；门面未重导出 `TalismanState`，用稳定的 `state.label()` 映射，六个终态由单测锁住。

### 三条红线在界面上的落点

| 红线 | 落点 |
|---|---|
| dry-run 之前不给焚符按钮；焚符须**勾选**确认 | `ritual_button(Ignite)` 的 `enabled = plan.is_some() && !burning && confirm_checked`；门面 `ignite(confirmed)` 兜底 |
| 焚化在后台线程，界面不卡死、不假装思考 | 焚化卡片 = spinner + 中止按钮；**不使用假进度条** |
| 保留中文 IME 探针（M0 未完成真人验收项） | 状态栏折叠区，重做界面也未隐藏 |

### 双闸门

1. 整符级：`我确认焚化不可撤销`（勾选框）。
2. 逐次级：敕门卡片（默认逐次问人、fail closed）；勾选「预授权」是显式例外，且会记入缴符。

两道闸门视觉上分层，绝不合并成一个确认框。

| 前景 | `VOID` | `ALTAR` | `RAISED` | `SUNKEN` | 判定 |
|---|---|---|---|---|---|
| `INK` | 15.66 | 14.91 | 13.73 | 15.99 | AA+ |
| `INK_SOFT` | 9.74 | 9.27 | 8.54 | 9.94 | AA+ |
| `INK_MUTED` | 5.34 | 5.08 | **4.68** | 5.45 | AA（下限） |
| `CINNABAR` | 5.69 | 5.42 | 4.99 | 5.81 | AA |
| `GOLD` | 10.95 | 10.42 | 9.59 | 11.17 | AA+ |
| `JADE` | 9.44 | 8.99 | 8.28 | 9.64 | AA+ |
| `EMBER` | 8.13 | 7.74 | 7.12 | 8.30 | AA+ |
| `ST_EXPLODED` | 6.30 | 5.99 | 5.52 | 6.43 | AA |
| `ST_CANCELLED` | 7.85 | 7.47 | 6.88 | 8.01 | AA |

其他判据：

- 交互控件边界 `EDGE`：`3.90:1`（ALTAR）/ `3.59:1`（RAISED）≥ 3:1（WCAG 1.4.11）。
- 符纸小字：`PAPER_INK` 12.46、`PAPER_BROWN` 5.12、`SEAL_RED` 4.81（均在 `PAPER` 上 ≥ 4.5）；缺段灰字 5.54。历史值 `#8A6A3B`(4.06) 与 `#C0392B`(4.42) 已校准。
- 朱砂按钮 `INK_ON_RED` on `CINNABAR_DEEP` = 5.50:1。
- 交互目标 ≥ 30px 高，焦点走 egui 原生 `focus-visible`；hover/active 有 1px 扩张与描边提亮。
- 动效全部短时长且可被打断；无闪烁、无自动播放循环。
- **未验事项如实标注**：中文 IME 真人验收（T37 已过 10/10，但 150%/200% 缩放、微软拼音/搜狗、mac/Linux 未测）、符纸与太极视图的颜色/字号/动画节奏「只有数字判断，没有眼睛判断」（`docs/02` §28/§36）。本次重做**没有**把这些标成已通过。

## 7. 符文界面专项设计

**为什么独立成屏**：符纸是单一信息载体（九段 ↔ 字段一一对应），不该被表单列表取代，也不该塞在滚动栏顶部当一小块缩略图。它是全台唯一亮面，需要自己的案台与呼吸空间。

- **案台**：`SUNKEN` 暗木衬底 + 四角暗金钉，纸放在 12px 内边距上，形成"放上去"而不是"贴上去"的层次。
- **金纸**：3:5 竖长方、圆角 0、双层边框（外 2px 暗金 / 内 0.6px）；符头三清点 + 两侧卷云是**抽象几何装饰，明确不是云篆书法字形**。
- **纸面尺寸**：符纸是主视觉，不再沿用旧版右栏缩略图的 `120..=240` 宽度。`paper::fit` 按可用宽度的 44% 给纸（右侧信息栏仍留得住），夹在 `260..=380`，高度按 3:5 再由可用高度 0.78 收一次、保底 360；整栏可滚，纸再大也不会把表单挤出屏幕。**真窗口复核暴露过这个落差**：升格成独立一屏后没改尺寸规则，18 字段正文与 11px 中文挤成一团；现锁进 `studio_paper_is_bigger_than_the_old_thumbnail` 回归测试。
- **九段**：左侧等宽段号（`PAPER_MIN` = 11px，历史 9px 已修）、段名（纸面棕）、正文（纸面墨）。窄段（< 30px）自动切紧凑单行排版。段间 0.5px 暗金细线。
- **纸面文字不越界**：正文按可用像素宽度裁剪，超出补 `…` **显式标注截断**，绝不溢出纸边框糊到下一段，也绝不静默丢字；数据层 `clip` 与本层 `elide` 都是同一条诚实性约束的两道实现。
- **缺段**：数据判断 `zone.filled == false` → 灰底 + 顶部虚线 + 「未成符」，绝不假装整张符完整。
- **朱砂方印**：仅 `self.seal` 有值时盖；双框 + 印文「符」+ 符印前 8 位。
- **火光 / 笔顺**：纯视觉（`Honesty::DisplayOnly` 标注），不承载任何状态判定。
- **热区**：点段 → 选中朱砂淡洗 + 左强调条 → 展开字段表单对应项；hover 显示字段名与「已填 / 留空」。**无伪交互**（没有内嵌可编辑控件、没有粒子系统、没有"点一下变金色"）。
- **数据来源**：版式全部来自 `paper::plan`（背后 `fulu-script::describe_cloud`），GUI 只把归一化坐标乘成像素，不二次折行——否则 CLI 与界面排版会分叉。

## 8. 开发者交接

### 文件清单

| 文件 | 职责 |
|---|---|
| `crates/fulu-ui/src/theme.rs` | 全部设计令牌 + `install(ctx)` 装配 egui `Visuals`/`Style` + WCAG 单测 |
| `crates/fulu-ui/src/widgets.rs` | 纯绘制组件（不认识 `FuluApp`、不碰门面）+ 标注原子单测 |
| `crates/fulu-ui/src/main.rs` | 绘制层：`top_bar` / `status_bar` / `left_panel` / `right_panel` / `center` + `altar_view` / `paper_studio` / `paper_view`；业务函数一律未改 |
| `crates/fulu-ui/src/paper.rs` / `taiji.rs` | **纯数据契约，不 import egui**（架构铁律）；`paper.rs` 本轮只把 `fit` 从缩略图尺寸改成案台尺寸并补回归单测，九段版式/热区逻辑未动 |

### 改设计时的顺序

1. 改 `theme.rs` 的令牌 → 2. 跑 `cargo test -p fulu-ui`（对比度单测会拦住不达标的改色）→ 3. 改 `widgets.rs` / 绘制层 → 4. 同步本文与 HTML 预览 → 5. 全套门禁。

### 禁止事项

- ❌ 在 `main.rs` / `widgets.rs` 里写裸 `Color32::from_rgb(...)`（必须用 `theme::c::*`）。
- ❌ 给六终态复用同一个「失败红」。
- ❌ 把权限与风险合并成一根危险度滑块。
- ❌ 在缴符时间线加删除/编辑/拖拽控件。
- ❌ 把流式增量、火光、笔顺、太极层视图画得像"结果"或"可停"。
- ❌ 把 `UNVERIFIED` / `估算` / `已截断` 悄悄吞掉。
- ❌ 让 GUI 直接依赖 `fulu-core` / `fulu-runtime`（只经 `fulu-app` 门面）。
- ❌ 用 WebView / HTML 做产品界面（HTML 仅用于**设计预览**，不是产品）。
